# Сбор мер поддержки АПК

В составе Docker Compose worker запускается автоматически после готовности бота и повторяет обработку раз в 24 часа. Настройка всей системы описана в [корневом README](../README.md#быстрый-запуск-через-docker-compose).

Worker собирает данные по Ивановской области и каталогу «Своё Фермерство», затем размечает направления хозяйства через GigaChat. Подбор под профиль фермера пока не выполняется.

## Источники

| `source` в БД | Данные | Статус источника |
| --- | --- | --- |
| `ivanovo_official_support` | Перечень мер и ссылки на нормативные акты | Официальный сайт департамента |
| `ivanovo_official_selections` | Объявления текущего года и тексты PDF | Официальный сайт департамента |
| `svoefermerstvo_federal` | Карточки каталога «Своё Фермерство» | Вторичный каталог, среди карточек есть меры отдельных регионов; имя `source` историческое и не подтверждает федеральный охват |

Адреса источников приведены в [docs/SOURCES.md](../docs/SOURCES.md). Портал `promote.budget.gov.ru` не подключён: публичная главная страница блокирует автоматическое чтение, а подтверждённого API для конкретных отборов у нас пока нет.

## Запуск без Docker

Из корня репозитория:

```powershell
python -m pip install -r worker/requirements.txt
$env:PYTHONPATH = "worker"
python -m app.main --dry-run --sample 1 --max-pdfs 3
python -m app.main
python -m app.main --classify-only --classification-limit 10
```

Команду нужно выполнять из корня с `PYTHONPATH=worker` либо непосредственно из каталога `worker`. Если запустить её из корня без `PYTHONPATH`, Python выдаст `No module named 'app'`.

Строки `DATABASE_URL`, `GIGA_API_KEY`, `GIGACHAT_MODEL` и `GIGACHAT_SCOPE` читаются из переменных окружения или корневого `.env`. Поддерживаются адреса PostgreSQL `postgresql://...` и `postgresql+psycopg://...`. По умолчанию используются модель `GigaChat-2` и scope `GIGACHAT_API_PERS`; для другого типа ключа укажите его scope. Для TLS используется `backend/certs/russian_trusted_root_ca.pem`, если он существует. При необходимости задайте `GIGACHAT_CA_BUNDLE`. Первый запуск создаёт или дополняет таблицы по [SQL-схеме](sql/001_support_ingestion.sql).

Разовый полный цикл выполняется командой `python -m app.main`: сбор, извлечение дедлайнов, summary и классификация направлений. Для ежедневного повтора используется `python -m app.main --loop`.

## Запуск worker в Docker

При обычном `docker compose up --build -d` контейнер уже работает с `--loop`. Для ручного запуска остановите плановый процесс:

```powershell
docker compose stop worker

# Полный цикл
docker compose run --rm --no-deps worker python -m app.main

# Только один источник
docker compose run --rm --no-deps worker python -m app.main --source federal_catalog

# Только сбор данных без трёх GigaChat стадий
docker compose run --rm --no-deps worker python -m app.main --source federal_catalog --skip-deadlines --skip-summary --skip-classification

# Обработка уже сохранённой базы
docker compose run --rm --no-deps worker python -m app.main --deadline-only
docker compose run --rm --no-deps worker python -m app.main --summary-only
docker compose run --rm --no-deps worker python -m app.main --classify-only

docker compose start worker
```

`db` должна быть запущена. Если она остановлена, сначала выполните `docker compose up -d db bot`.

## Основные параметры CLI

| Параметр | Что делает |
| --- | --- |
| `--source all` | все источники; также доступны `ivanovo_support`, `ivanovo_announcements`, `federal_catalog` |
| `--dry-run --sample 2` | скачать и распарсить без записи в БД, вывести примеры |
| `--year 2026` | год официальных объявлений Ивановской области |
| `--max-pdfs 50` | максимальное число новых PDF объявлений |
| `--max-support-documents 100` | предел нормативных файлов регионального перечня |
| `--max-federal-pages 200` | защитный предел страниц каталога «Своё Фермерство» |
| `--federal-detail-workers 4` | число параллельных запросов детальных карточек |
| `--deadline-only` | только дедлайны для записей в БД |
| `--summary-only` | только краткие описания для записей в БД |
| `--classify-only` | только направления для записей в БД |
| `--skip-deadlines`, `--skip-summary`, `--skip-classification` | пропустить соответствующую стадию полного цикла |
| `--deadline-limit N`, `--summary-limit N`, `--classification-limit N` | ограничить пробный запуск |
| `--force-deadlines`, `--force-summaries`, `--force-classification` | повторить обработку неизменившихся текстов |

## Разметка направлений

Допустимые значения читаются из `backend/src/activity_labels.ts`. Для каждой меры worker отправляет в GigaChat заголовок, условия и доступные тексты документов небольшими фрагментами. Ответ принимается только с метками из справочника и цитатами, найденными в соответствующем фрагменте. Неподтверждённые находки отбрасываются. Явные исключения хранятся отдельно от поддерживаемых направлений. Общая отрасль не добавляется автоматически к узкой метке.

Результат находится в `support_measures.activity_labels` (`text[]`). `activity_scope` принимает `specific`, `all` или `unknown`; `all` означает, что в тексте прямо указана поддержка без ограничения по направлениям. `activity_status` принимает `pending`, `classified`, `needs_review` или `error`. Цитаты и ссылки на текст хранятся в `activity_evidence`, исключения — в `activity_exclusions`. Если полного текста нет или модель дала непроверяемую цитату, запись остаётся `needs_review`. Повторная обработка пропускает записи с тем же текстом, моделью и справочником.

Worker скачивает нормативные PDF и DOCX, на которые ссылается региональный перечень. Тексты новых PDF извлекаются по всем страницам до 1 млн символов с маркерами страниц. Превышение предела помечается `text_truncated`; PDF без текстового слоя — `no_text_layer`. Старый формат `.doc` пока получает `unsupported_format`. Ранее сохранённые PDF без маркеров страниц считаются неполными до повторного сбора.

Каталог «Своё Фермерство» проходит все страницы пагинации, а затем открывает каждую детальную карточку. Из списка берутся название, краткий текст, основные условия, получатели и размер; детальная страница добавляет подробные условия, доступные регионы и нормативные ссылки. Временная ошибка детальной страницы не заменяет уже сохранённый подробный текст сокращённой карточкой. Запросы повторяются и выполняются с ограниченной параллельностью. Защитный предел `--max-federal-pages` по умолчанию равен 200; если страниц станет больше, сбор завершится ошибкой, пока предел не будет явно увеличен.

## Данные для backend

`support_measures` содержит название, регион (`NULL`, когда регион пока не определён), вид `measure` или `selection`, описание, текст условий, дату публикации и, когда он надёжно извлечён из PDF, срок приёма заявок. `support_documents` содержит ссылки на документы и извлечённый текст. Если PDF является сканом без текстового слоя, `extraction_status='no_text_layer'`; OCR пока нет. Для неизвестного срока `application_deadline` остаётся `NULL`, поэтому backend не должен считать такую меру открытой без отдельной проверки.

У карточек `svoefermerstvo_federal` регион извлекается из детальной страницы, когда портал его перечисляет. `region=NULL` означает «регион на странице не определён», а не подтверждённую доступность по всей России. Среди карточек есть меры других областей; до проверки региона нельзя использовать их для автоматического подбора по Ивановской области.

Для карточек бота worker заполняет `short_description` через GigaChat: весь доступный текст меры и извлечённых документов разбивается на фрагменты, по ним строятся промежуточные конспекты, затем модель собирает итоговую выжимку до 360 символов. Для уже сохранённых строк это можно запустить командой `python -m app.main --summary-only --force-summaries`. `support_type` определяется по явному упоминанию типа поддержки, а `application_url` пока содержит страницу источника, где найдена мера или объявление; это **не подтверждённая прямая ссылка на подачу заявки**. `kind` по-прежнему означает `measure` или `selection`, а не «субсидия» или «грант».

Даты приёма заявок дополнительно извлекаются GigaChat из доступного текста меры и документов. Перед вызовом модели worker отбрасывает фрагменты без конкретной календарной даты: без даты в источнике надёжный дедлайн записать невозможно. Для остальных фрагментов модель определяет контекст, возвращает дату с дословной цитатой, а worker проверяет цитату и саму дату. При нескольких разных дедлайнах запись получает `deadline_status='needs_review'`, а текущая дата не заменяется. Для уже собранной базы: `python -m app.main --deadline-only`. `--deadline-limit 10` ограничивает пробный запуск, `--force-deadlines` перепроверяет даже неизменившиеся тексты.

На «Своём Фермерстве» поле вида «До 18 месяцев» обозначает срок освоения средств. Это не срок подачи заявки, поэтому worker его в `application_deadline` не записывает. Многие карточки портала вообще не содержат периода приёма; для них дата остаётся `NULL` до появления официального объявления или другого подтверждённого источника.

Идентификатор `(source, external_id)` уникален. Повторный сбор обновляет запись и `last_seen_at`, сохраняя `first_seen_at`. Сбой одного источника не отменяет результаты остальных; журнал каждого запуска хранится в `support_ingestion_runs`.

## Тесты и экспорт

Из корня репозитория:

```powershell
$env:PYTHONPATH = "worker"
python -m unittest discover -s worker/tests -v
python test.py
```

Экспорт записывает полное содержимое в `parsed_data.json` и основные карточные поля в `parsed_data.csv`.
